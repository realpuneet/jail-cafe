## Dependency audit

Run on 2026-10-12:

- `frontend`: `npm audit --omit=dev` → **0 vulnerabilities**.
- `backend`: `npm audit --omit=dev` → **2 moderate**, both `uuid <11.1.1` (GHSA-w5hq-g745-h8pq, missing bounds check in `v3/v5/v6` **when a caller passes a `buf` argument**) reached through the `imagekit` SDK. We use the SDK only for signed upload parameters and file deletion and never pass a buffer to uuid, so the vulnerable path is not reachable. The suggested fix is a breaking downgrade of `imagekit`; we track the upstream release instead. Re-run `npm audit` in CI before each release.

## Known limitations / manual items

- Live Razorpay, ImageKit, MSG91 and WhatsApp calls were not exercised (no credentials in the build sandbox); their request shapes follow the vendor docs and are covered with stubs.
- Docker images were not built in the sandbox (no Docker daemon). CI builds the backend image; the frontend image is built in CI only after you enable it.
- A third-party penetration test and a WAF/DDoS layer (Cloudflare or similar) are recommended before public launch.
- Rotate JWT secrets by deploying a new `JWT_REFRESH_SECRET`; all sessions are then invalidated (acceptable, users log in again by OTP).
